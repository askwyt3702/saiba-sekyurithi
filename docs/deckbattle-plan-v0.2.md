# ローグライク・カードバトル 試作開発計画書 v0.2

2026-11-18 · チーム共有用(共有ドキュメント版: https://claude.ai/artifact/DKdcJCTTGfS8na76ivwkqf)

v0.2 では、サイバーセキュリティの世界観を残し、今の問題集を「イベントマス」のクイズにして、使うほど育つカードとつなげる。正解するとカードの経験値が増えるので、学習とゲームの強さが結びつく。数値はすべて試作用の仮の値で、プレイテストで調整する。

> このファイルは共有ドキュメントの写し。内容を変えるときは、共有ドキュメントとこのファイルの両方を更新する。

## 1. v0.1 からの変更点

世界観を残し、クイズをイベントマスとして復活させた。あわせて、元のゲームに近すぎる数値と、後から手に入れたカードが育たない経験値の設定を見直した。

| 項目 | v0.1 | v0.2 |
| --- | --- | --- |
| 世界観 | サイバーセキュリティ要素は入れない | サイバーのまま。カード名・敵・用語を攻撃手法と防御の言葉にする |
| クイズ・学習 | 入れない | イベントマスで出題。正解でカードに経験値 +2 |
| 1回のランの流れ | 戦闘3回 + ボス | 戦闘 → イベント → 戦闘 → イベント → 戦闘 → ボス |
| 初期デッキ | 斬撃5・防御4・集中1 | SSH辞書攻撃4・ファイアウォール4・ポートスキャン1・セッションハイジャック1 |
| エネルギー・ドロー | エネルギー3・5枚 | 帯域4・4枚 |
| プレイヤーの HP | 60 | 回線耐久 65 |
| Lv.2 / Lv.3 に必要な経験値 | 3 / 8 | 2 / 5(報酬のカードも1回のランで Lv.3 に届く) |
| カードの組み合わせ・状態異常 | 決まりなし | 7章で決める |
| 敵 | HP の目安だけ | 4戦闘分の敵と行動を8章で決める |

数値を変えた理由:「初期デッキ10枚(攻撃5・防御4・特殊1)」「エネルギー3・5枚ドロー」は元のゲームの最初の状態とほぼ同じだったため。v0.1 の方針「固有の要素をそのまま複製しない」に合わせた。

## 2. 企画方針と決定事項

短時間で繰り返し遊べるデッキ構築型のカードバトルを、サイバーセキュリティの世界で作る。以下は決定済み。

- **ジャンル**:ローグライク・カードバトル。ターン制。1回のランは5〜10分。
- **独自要素**:すべてのカードが1枚ずつ経験値を持ち、使うほど育つ。Lv.3 で、決めておいた進化先から好きなものを選ぶ(固定分岐型)。同じ名前のカードでも、別々の進化先にできる。
- **世界観**:プレイヤーは侵入するハッカー、敵は防御システム。カードは実在の攻撃手法と防御策で、説明文がそのまま仕組みの解説になる。今のダークな画面・BGM・効果音を引き継ぐ。
- **学習要素**:今の問題集(135問)をイベントマスのクイズとして出す。正解でカードが育ち、正解・不正解どちらでも解説を見せる。
- **レア度**:コモン/アンコモン/レア。コモンとアンコモンは2分岐、レアは3分岐。
- **参考の仕方**:既存作品はジャンルとテンポの参考にとどめる。固有のカード名・カードの一覧・アート・UI・文言・演出、初期状態の数値をそのまま使わない。
- **ターン制**:チームで決めたとおり、実時間で進む仕組みは入れない。

## 3. 試作の完成条件(MVP)

次の流れが、ブラウザ上でエラーなく最後まで遊べれば試作完成とする。1回のランは6マスで、分岐マップは作らず固定の順番で進む。

1. タイトル
2. 戦闘1(スキャナーbot)→ 勝利報酬 → カードのレベルアップ/進化
3. イベント1(クイズ)→ カードのレベルアップ/進化
4. 戦闘2(IDSセンサー×2)→ 勝利報酬 → レベルアップ/進化
5. イベント2(クイズ)→ レベルアップ/進化
6. 戦闘3(ファイアウォールAI)→ 勝利報酬 → レベルアップ/進化
7. ボス(ARGUS)
8. 結果画面(勝ち・負け、育てたカードの一覧)→ もう一度遊ぶ

この中で必ず動かすもの:

- ターン制の戦闘:手札・山札・捨て札・帯域(エネルギー)・攻撃・ファイアウォール(ブロック)・敵の行動の予告・勝敗
- 戦闘の報酬:カード3枚から1枚をもらうか、スキップ
- カードの成長:1枚ごとの経験値、Lv.2 は自動で強化、Lv.3 は進化先を選ぶ
- イベントマス:クイズ1問と解説、正解・不正解の結果
- ランの間、カードの状態と HP を引き継ぐ。ボス撃破・敗北で結果を出し、最初からやり直せる

## 4. 戦闘ルール(試作用の仮の数値)

1ターンは「カードを使う → ターン終了 → 敵が予告どおり行動 → 次のターン」。最優先は遊べることで、数値はプレイテストで調整する。

| 項目 | 試作の設定 |
| --- | --- |
| プレイヤーの HP(回線耐久) | 最大65、開始65。ランの間は引き継ぐ |
| 帯域(エネルギー) | 毎ターン4。使い切れなかった分は次のターンに持ち越さない |
| ドロー | 毎ターン4枚。使わなかった手札はターン終了時に捨て札へ |
| 山札が尽きたとき | 捨て札をシャッフルして山札にする |
| ファイアウォール(ブロック) | 受けるダメージをその分減らす。プレイヤーのターン開始時に0に戻る |
| 初期デッキ(10枚) | SSH辞書攻撃4、ファイアウォール4、ポートスキャン1、セッションハイジャック1 |
| 通常の敵の HP | 26〜40(1体あたり、16×2体の戦闘あり) |
| ボスの HP | 120 |
| 勝利 | 敵を全部倒す。報酬はカード3枚から1枚、またはスキップ |
| 敗北 | プレイヤーの HP が0以下でラン終了 |
| 戦闘の間の回復 | 戦闘に勝つと HP を最大の10%(6)回復 |

敵が複数いるときは、攻撃カードを選んでから対象の敵をクリックする。全体攻撃は対象を選ばない。

## 5. カードの成長・進化ルール

Lv.2 は経験値2、Lv.3 は経験値5。戦闘1でもらったカードも、よく使えば戦闘3の前に Lv.3 に届く。

| 状態 | 条件 | 処理 |
| --- | --- | --- |
| Lv.1 | はじめ | 基本の効果 |
| Lv.2 | 累計経験値 2 | 戦闘・イベントの後に自動で強化 |
| Lv.3 | 累計経験値 5 | 戦闘・イベントの後に、決めておいた進化先から1つ選んで最終進化 |

経験値の入り方:

- カードを1回使うごとに +1。
- 戦闘に勝ったとき、その戦闘で1回以上使ったカードにさらに +1。
- 1回の戦闘で、1枚がもらえるのは最大3。同じ安いカードばかりを使い続けるだけで育ちきらないようにするため。
- イベントのクイズに正解すると、好きなカード1枚に +2(上の上限とは別)。

その他の決まり:

- 戦闘中は経験値を足すだけ。レベルアップと進化先の選択は、戦闘に勝った後とイベントの後にまとめて行う。
- 同じ名前のカードも、1枚ずつの個体 ID で経験値を管理する。
- 進化待ちのカードが複数あるときは、順番に選ぶ。選び終わるまで次のマスに進めない。
- 進化はランの間だけ続き、ランが終わると元に戻る。進化した後に選び直すことはできない。
- Lv.3 の進化先は経験値だけで開く。使い方による絞り込みはしない。
- カードには「Lv.2 → あと1で Lv.3」のように経験値を表示し、レベルアップの瞬間に演出を入れる。

## 6. MVP のカード6種類

v0.1 の6種類と同じ仕組みで、名前だけを攻撃手法にした。EN = 帯域(エネルギー)、FW = ファイアウォール(ブロック)。MVP では6種類とも分岐は2つ。

| カード(v0.1 の名前) | レア度 | Lv.1 | Lv.2 | Lv.3 分岐A | Lv.3 分岐B |
| --- | --- | --- | --- | --- | --- |
| SSH辞書攻撃(斬撃) | コモン | 1EN/6ダメージ | 9ダメージ | 総当たり連打:1EN/4×3 | 認証突破:2EN/18 |
| ファイアウォール(防御) | コモン | 1EN/FW5 | FW8 | 多層防御:1EN/FW12 | リバーストラップ:1EN/FW7+次に受ける攻撃に5反撃 |
| DDoSフラッド(火球) | コモン | 1EN/7ダメージ | 10ダメージ | ボットネット:2EN/敵全体12 | 過負荷:1EN/8+過熱4 |
| ポートスキャン(集中) | コモン | 0EN/1枚引く | 2枚引く | 全ポート走査:1EN/2枚引く+帯域1回復 | 脆弱性特定:1EN/次の攻撃+8 |
| セッションハイジャック(吸収) | アンコモン | 1EN/5ダメージ | 7ダメージ | トークン窃取:1EN/8+HP3回復 | 権限奪取:1EN/6+1枚引く |
| スクリプト自動化(加速) | アンコモン | 1EN/次の攻撃+3 | 次の攻撃+5 | 並列実行:1EN/次の攻撃カードを2回発動 | マクロ化:0EN/1枚引く+次のカード−1EN |

- カードの説明には、効果の下に1行で「実際の攻撃・防御の仕組み」を書く(例:SSH辞書攻撃 = よく使われるパスワードを端から試す)。
- 拡張目標(MVP 完成後):12種類(コモン6・アンコモン4・レア2)、最終40種類(コモン20・アンコモン12・レア8)。レアは3分岐。

## 7. カードの組み合わせと状態異常の決まり

組み合わせで結果が変わるカードは、以下のとおりに処理する。実装もテストもこの表を基準にする。

| 対象 | 決まり |
| --- | --- |
| 「次の攻撃+N」 | 次に使う攻撃カード1枚に乗る。複数回攻撃(4×3)なら各回に、全体攻撃なら各敵に加算。重ねがけすると合計。そのカードを使ったら消える |
| 「次の攻撃カードを2回発動」 | 次の攻撃カード1枚の効果を丸ごと2回。+N は2回ともに乗り、2回目の後に消える。経験値は使った1回分(+1)だけ |
| 「次のカード−1EN」 | 次に使うカード1枚(種類を問わない)。コストは0未満にならない |
| 過熱 N | 敵のターン終了時に N ダメージ(FW を無視)。3ターン続く。重ねると N を足し、残りターンは3に戻る |
| 反撃 N | 次に受ける攻撃1回で、攻撃してきた敵に N ダメージ。FW で全部防いでも発動する |
| FW(ブロック) | ダメージから先に引かれる。余った分はプレイヤーのターン開始時に消える |
| 回復 | 最大 HP を超えない |
| ノイズ(敵が入れるカード) | 使えないカード。手札に来ると枠をふさぐ。戦闘が終わるとデッキから消える |

この決まりで組むと、「脆弱性特定(+8)→ 並列実行 → 総当たり連打(4×3)」は (4+8)×3×2 = 72 ダメージになる。強すぎる場合は、並列実行のコストを2EN に上げて調整する。

## 8. 敵(MVP の4戦闘分)

敵は次のターンの行動を必ず予告し、予告どおりに動く。行動は表の順に繰り返す(ランダムにしない)。

| 戦闘 | 敵 | HP | 行動の順番 |
| --- | --- | --- | --- |
| 1 | スキャナーbot | 28 | 攻撃6 → FW6 → 攻撃8 |
| 2 | IDSセンサー ×2 | 各16 | 攻撃4×2 → 検知(プレイヤーの次のターンの帯域−1)。2体は1ターンずらして動く |
| 3 | ファイアウォールAI | 40 | FW10+攻撃5 → 強化(攻撃+3、戦闘中ずっと) → 攻撃12 |
| ボス | 監視AI ARGUS | 120 | HP 半分まで:攻撃10 → FW12 → ノイズ注入(ノイズ2枚を捨て札へ)。HP 半分以下:攻撃7×2 → 攻撃18 → ノイズ注入 |

- 予告の表示は、敵の頭の上に「⚔ 10」「🛡 12」「☣ ノイズ」のようにアイコンと数字で出す。
- 敵の行動は1つずつ演出して見せる(攻撃の光、ダメージの数字、効果音)。今の陣取りゲーム用に作った演出を使い回す。
- 戦闘2は、全体攻撃(ボットネット)が意味を持つように2体にした。

## 9. イベントマス(クイズ)

イベントマスでは、今の問題集から1問(3択)を出す。正解の報酬をカードの経験値にして、学習とカードの成長をつなげる。不正解の罰は軽くして、クイズを避けたくならないようにする。

| イベント | 内容 | 正解したら | 間違えたら |
| --- | --- | --- | --- |
| イベント1:脆弱性診断 | 攻撃手法を選ぶ問題 | 好きなカード1枚に経験値 +2 | HP −5 |
| イベント2:パッチ適用 | 設定やコードの不備を見つける問題 | 経験値 +2 に加えて、HP 15回復かカード1枚の削除を選ぶ | なし(解説だけ) |

- 問題は `frontend/src/game/data/securityLearningData.ts` の135問を使う。問題文、選択肢、選択肢ごとの解説(`feedback`)、危険な理由(`whyDangerous`)、対策(`defenseMeasure`)がそろっている。
- 正解・不正解のどちらでも、解説と対策を必ず見せてから次に進む。
- 1回のランで同じ問題は出さない。
- イベント1は TYPE A(攻撃手法の特定)、イベント2は TYPE B(設定・コード解析で不備を見つける)の問題から選ぶ(`questionType` で絞る)。TYPE C(攻撃コマンドの選択)は難しめなので、MVP では使わない。
- 経験値をもらった後に Lv.2・Lv.3 に届いたカードは、その場でレベルアップ/進化の画面に進む。
- 将来の拡張:攻撃のログを読んで何が起きたか当てる「インシデント対応」、分岐マップでの休憩マスなど。

## 10. 実装方針

新しいゲームはブラウザの中だけで動かし、バックエンドは使わない。今のゲームは、新しい試作が最後まで遊べるようになるまで消さない。

**置き場所**

- ルール(戦闘・カード・成長・ラン):`frontend/src/game/deckbattle/`。画面に依存しない純粋な関数で書き、`node --test` でテストする
- 画面:`frontend/src/components/DeckBattle/`
- 入り口:ミッション選択画面に新しいカードを追加する(今のミッションは残す)

**使い回せる部品**(陣取りカードゲームのブランチ `feature/territory-readability` と main にある)

- 手札・山札・捨て札・ドロー・報酬3択の処理
- カードの見た目(コストの宝石、種類の色の帯、絵柄、レア度の枠)
- 敵の行動の予告と1つずつの演出、ダメージの数字
- 効果音(`frontend/src/game/sound/soundEffects.ts`)、警戒度で変わる BGM の試作(ブランチ `prototype/bgm-effects`)
- 画面の拡大縮小(`frontend/src/uiScale.ts`)
- 問題集(`frontend/src/game/data/securityLearningData.ts`)

**AGENTS.md のルールとの関係**

- 「バックエンドを変えたら生成ファイルを更新」「Mock とバックエンドを合わせる」は、新しいゲームには関係しない。
- 画面の CSS(`vh`/`vw` を使わない)、コミットメッセージ、コミット前のチェック(typecheck・lint・test・build)はそのまま守る。
- 試作が動いたら、AGENTS.md の「プロジェクトの前提」に新しいゲームのことを書き足す。

**データの形**(実装を始める前に合意する)

| 型 | 中身 |
| --- | --- |
| CardDefinition | カード ID、名前、レア度、種類(攻撃・防御・補助)、Lv.1/Lv.2 のコストと効果、進化先の一覧(ID・名前・コスト・効果)、仕組みの解説1行 |
| CardInstance | 個体 ID、基本カード ID、レベル、累計経験値、進化先 ID(Lv.3 のとき)、この戦闘で使った回数 |
| BattleState | プレイヤーの HP・FW・帯域、山札・手札・捨て札、敵(HP・FW・行動の予告・状態異常)、次の攻撃への修正、ターン数 |
| RunState | デッキ(CardInstance の一覧)、HP、今いるマス、マスの並び(戦闘・イベント・ボス)、進化待ちのカード、出題済みの問題、結果 |

ブラウザを読み込み直したときは、MVP ではランを最初からやり直す(保存しない)。

| D:イベント(クイズ) | 問題の選び方、解説の表示、正解・不正解の結果 | 2種類のイベントが動く | barcelonayuto-hash(セキュリティの問題を作った) |

## 12. 開発順序・マイルストーン

M1 → M2 → M3 → M4 の順に統合する。日付は提出日が決まってから入れる。

1. **M1 基盤**:データの形、初期カード、敵(スキャナーbot)、ターンの処理。完了 = 1回の戦闘が最後までできる
2. **M2 成長**:1枚ごとの経験値、Lv.2 の自動強化、Lv.3 の進化先を選ぶ画面。完了 = 進化の前後で効果が切り替わる
3. **M3 ラン**:4回の戦闘、報酬、2回のイベント(クイズ)、ボス、結果画面。完了 = 最初からボスまで通しで遊べる
4. **M4 仕上げ**:不具合の修正、数値の調整、遊び方の説明、効果音と BGM。完了 = 何回遊んでも進めなくならない

各担当は小さな PR で出し、main に直接大きな変更を重ねない。作業は必ず最新の main から始める(ここ数日の衝突の原因のほとんどは、古い main からの作業だった)。

## 13. 最低限のテスト・完成チェック

ルールのテストは `npm test` で自動で確かめ、画面の項目は通しプレイで確かめる。

**戦闘**
