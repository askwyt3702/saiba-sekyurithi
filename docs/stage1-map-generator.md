## 利用方法

Backendをimportできる環境で次を呼ぶ。DB・サーバーは不要。

```python
from map_generation import generate_stage1, GenerationFailure

try:
    generated = generate_stage1("00000000000000000000000000000000")
    definition = generated.definition  # 既存GameMapDefinition
    proofs = generated.validation.routes
except GenerationFailure as error:
    print(error.seed, error.rejected)
```

seedは32桁の16進文字列。大文字は小文字へ正規化するが、前後空白・桁不足・非16進・
非文字列は拒否する。自動seed発行、時刻、Python random/hash、Math.randomは使用しない。
同seed・生成版・検証版・設定・固定データ（config_hash）なら同じ候補・採択番号・盤面・証拠を返す。
ゲーム用の秘密鍵文字・gameIdはseedから生成しない。検証用のABCD/EFGHは証拠再生だけの値。

## 生成方法

完成済みマップや辺リストのプリセットは持たない。

1. Stage1の固定24ノードをコピーする。External3・DMZ7・Internal10・Core4と、
   ID・名称・説明・脆弱性・問題・効果・初期値・コストを保つ。
2. 用途別の乱数列でノードプールを並べ替え、高速・隠密・資源の枝をその場で構成する。
   入口E01と目標C03は共通。中立DMZ/Internal/Coreの割当と攻略順を変え、
   D06・I03/I04・鍵・C04を隠密側、E03・I05・I09を資源側へ配置する。
   余ったノードも枝に属する環や寄り道として追加する。
3. 深さ・所属枝・階層・次数を制約しながら補助辺を抽選する。
   強い利益の寄り道を省略する辺を制限するが、最後は全接続を使って検証する。
4. 階層ごとに座標スロットを並べ替え、整数の余白変化を付ける。
   既存MapView範囲内に置き、幅210px・高さ150pxの矩形が重ならないことを検査する。
   これは初期の保守的な矩形検査であり、ブラウザでの文字折返しや辺の交差の最小化までは保証しない。
5. 検証済み候補のうち、最小候補番号を採択する。

既定の辺数は34〜40、次数2〜5。同階層か隣接階層だけを接続し、
無向辺の重複・自己ループ・未知ID・孤立・非連結・階層飛越し・座標異常を棄却する。
全ノードの役割は元IDへ固定するが、完成した配置/接続を固定パターンから選ばない。
構成法は3つの役割枝を共通原理とする。万能の自由グラフ生成器ではない。

## 実ルールでの検証と保証範囲

`initial_rule_state()`から`game_rules.transition()`へ各操作を渡す。
scan（許可設定で必要ならremoteScan）→必要な明示confirmInfo/completeAnalysis→
当該questionIdのサーバー正解exploitIdでbreach→C03のdataExtractを再生する。
鍵が揃ったときだけC03の侵入に認証を使用する。
資源上限・消費・補給・権限・確認/解析・ゲート・鍵・敗北判定は既存処理の結果をそのまま使う。
スキャン直後の敗北も飛ばさない。勝利した証拠以外は採択しない。
回復を無料扱いする等の簡易ルールは追加しない。現在の証拠は回復不要なルートを構築する。

全補助辺の追加後、E01→C03の単純経路を既定10ノードまで列挙し、
同じルールで再生して時間・警戒度・残資源のPareto候補を得る。
構築時の案より良いルートがあれば証拠を選び直す。
同じ攻略ノード集合を3方針とは数えない。

採択基準（初期プロファイル）：

- 高速：225〜255秒、最終警戒度40〜65%、残資源6以下。
- 隠密：高速より30〜90秒遅く、最終警戒度を15ポイント以上改善し、操作完了時のピークも低い。
- 資源：高速より30〜90秒遅く、残資源が高速より5以上多く隠密よりも多い。隠密より警戒度の負担がある。
- 3証拠が互いに支配されないこと。時間だけでなく安全性・資源を得る選択が成立すること。

さらにグラフ最短距離を、E01からC03までに必要な最少攻略ノード数の下限として使う。
合法な高速証拠が`ノード数下限×(最小scan時間＋breach時間)＋回収時間`と一致する場合だけ採択する。
これにより高速の最短時間を証明する。グラフの距離だけでクリア可能と判断することはない。

**保証するのは、採択した盤面に3つの実行可能な勝利手順が存在することと、高速証拠の時間最短性。**
単純経路以外の分岐順序・全回復操作・全誤答・長い寄り道を含む万能探索ではなく、
隠密/資源の大域的最適性や、任意の誤操作後の救済を保証しない。
初級向けの最終難度・読図しやすさは、UI接続後の人間によるプレイテストが必要。
例示seedでは各方針のC03誤答1回（警戒度+10・資源-1）後も勝利できることを追加テストしたが、全seedの採択条件ではない。

## 有界処理・失敗

既定は最大16候補、各候補は経路1024本・DFS状態10000個、経路長10ノードまで。
予算切れは不明として棄却し、未探索候補を成功扱いしない。
試行・探索上限は設定に含めてhash化し、同じ上限なら棄却列も再現する。
全候補が不合格ならGenerationFailure。seedを変更したり、既存固定図を返したりしない。
壁時計で採択候補を変えず、将来のAPIのタイムアウト/キャンセルは外側で実装する。
測定値は壁時計上限の保証ではない。

## 再現・言語間契約

乱数入力はUTF-8の`nullroute|{小文字seed}|{stream}|{counter}`、counterは0からの十進文字列。
SHA256の先頭4byteをbig-endian uint32にし、2^32の剰余部分を棄却して範囲化する。
Fisher–Yatesは末尾から実行。streamは
`stage1-sha256-v1/attempt/{候補番号}/roles|edges|layout`で用途分離する。
ID順・無向辺の向き・辺リスト順を安定化する。

config_hashは生成/検証版・設定・固定定義、map_hashは内部GameMapDefinitionの正規化JSONのSHA256。
辞書キーをソートし、setをソート済み配列へ変換、配列順は保持、整数値のfloatと負のゼロは整数へ、
空白なし・日本語はUTF-8、NaN/Infinityは禁止する。固定データ変更は再現条件の変更としてhashに表れる。
TS移植ではcamelCaseの公開DTOをそのままhashせず、この内部キーの正規化形式へ変換する必要がある。

`to_wire()`で既存Snapshot schemaへ変換できる。
`from_wire(..., supported_generator_versions=(GENERATOR_VERSION,))`を指定した往復をテストする。
通常のDB保存/ロードはまだfixed-v1のみを許可するので、今回の結果を通常ゲームへ保存・再開できるという意味ではない。
対応生成版の有効化とsource=generated等の公開/保存メタデータは、将来の接続段階で契約と一緒に追加する。

Mock生成器は未実装。ただし、同じ盤面を既存Mockへテスト注入し、3 seed×3方針で
資源・時間・警戒度・権限・攻略状態・確認履歴・鍵認証・評価が各行動後にBackend証拠と一致することを検証した。
次段階は共通ベクトルに基づくTS生成器/検証器の移植であり、Mockだけ別方式を追加しない。

## 実測（256 seed）

コマンド：`python scripts/benchmark_stage1_generator.py --seeds 256 --output <任意の結果JSON>`。
seedは0〜255を32桁16進にした固定群。全256で採択に成功し、すべて第1候補を採択。
座標256種類、接続256種類。中央値48.1ms、p95 93.5ms、最大112.5ms、合計13.33秒。
Windowsの本作業環境での値で、API待機時間や並行実行性能は含まない。
全seedで必ず成功終了する証明とは区別する。
棄却・再試行・上限失敗は、壊した第1候補を注入するテストでも確認している。
