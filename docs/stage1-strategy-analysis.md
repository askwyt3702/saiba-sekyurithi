## 結論

3方針の経路は既に成立するが、最短経路に大幅な警戒度削減と補給が重なっている。
現状を「最短は危険、安全は遠回り」と説明するのは正確ではない。
特に全Externalから開始できる仕様により、E03始動で最短・低警戒・補給を同時に取れる。
一律のコスト増加より、入口の意図確認、ノード効果の見える化、経路の役割整理、評価の統一を優先する。

## 確認が必要な仕様

1. 依頼文はリアルタイム制だが、AGENTS.md・実装はターン制。待機では時間も警戒度も変化せず、操作だけがゲーム内時間を進める。本分析は実装に従う。方式の変更は提案に含めない。
2. E01は「初期侵入口」と説明されるが、実装はExternal全体が入口。E02/E03始動は合法。入口をE01に限定する意図なのか、複数入口を残すのかはチーム確認が必要。
3. データ回収で警戒度100になっても勝利する。勝利を設定してから敗北判定を行うため。これを脱出成功として維持するか、検知失敗にするかは仕様判断が必要。
4. C02の説明は回収認証を連想させるが、C02攻略は必須ではない。I09/C04の「防御弱体化」「緊急遮断停止」は現状では数値効果・ログの説明であり、独立した防衛システムは実装されていない。

### メリット・デメリットと詰み

- 最短：速く、かつ十分低警戒。残資源4なので追加の通常スキャン＋侵入は原則1ノード分まで。ミスや追加探索では回復が必要になりやすい。ただし初期状態からこの手順なら危険経路とはいえない。
- 安全：警戒度ピークが低く、鍵で回収時の上昇を消せる。一方、追加90秒・残資源0。回収で勝つため正常終了できるが、回収前の追加消費は回復が必要。低警戒でも資源管理上は余裕がない。
- 資源：補給合計21で、探索・寄り道を増やしやすい。時間は最短より30秒長く、最終警戒度が約30.5ポイント高い。ただし45.25%は100%から離れており、無ミス時の破綻リスクは低い。

初期状態・指定手順ではいずれも詰まない。これは初見探索、操作の誤り、既に高い警戒度からの回復を保証するものではない。

### 特に重要な反例：最短と安全・補給が重なる

| 取得順序 | 時間 | 最終警戒度 | 残資源 | 画面得点 |
|---|---:|---:|---:|---:|
| E03 → D06 → I03 → I04 → I09 → C04 → C03 | 225秒 | 14.75% | 9 | 1005 / S |
| E03 → D06 → I05 → I06 → I10 → C02 → C03 | 225秒 | 39.75% | 21 | 985 / S |

1本目は提示結果の経路と同じ時間・最終警戒度で資源が5多く、確定後ピークも14.75%と低い。
2本目は同じ最短時間で資源21を残す。資源報酬の設定合計は21だが、I10で上限30に当たるため実受領は20。
この2本が、最短・安全・資源の役割を分けにくくしている。

| ノード | 実際の効果 | 問題・役割 |

| D06 | 警戒度−8 | 通信偽装。序盤では下限0により一部効果が余る |

| I09 | 資源+3、警戒度−10 | 通常スキャン＋侵入費3を返しつつ低警戒化。最短経路上の万能ノード |

鍵を取らない8ノード低警戒経路
`E01 → E03 → D06 → I03 → I04 → I09 → C04 → C03`
は255秒・警戒度14.75%・資源6・945点S。

## 回復・敗北・リモートスキャン

- 1ノードでも侵入済みなら、資源0から回復できる。回復は回数制限なしだが、1回ごとに30秒と警戒度10.5を払う。回復は十分な詰み防止になる一方、高警戒では安全な回復を保証しない。
- 最初の侵入前は回復できない。資源を最後のスキャンで使い切ると敗北することを実ロジックで確認した。
- 現在の手詰まり判定は「受理可能な操作があるか」であり、「勝利まで到達できるか」ではない。回復が受理されても、警戒度上昇で必ず敗北する局面までは先読みしない。
- 回復は上限直前でも使えて実際の獲得量が小さくなる。得られる資源と警戒度コストをUIで予告するとよい。
- リモートスキャンは隣接・権限を無視して侵入する手段ではない。隣接後に通常スキャンできるノードでは、資源+3・時間+15秒・警戒度+5.25の割増となる。情報を先に得る価値がUIで見えにくい。
- 高警戒からの回収の境界確認：鍵なしで95%/99%から回収すると100%でもwon、鍵ありで99%から回収すると98.25%でwon。鍵の「回収による検知を避ける価値」が現状の勝敗には反映されにくい。

## ランクの評価

画面は `max(0, round(1000 − max(0, 秒−200)×0.5 − 警戒度×8 ＋ 残資源×15))`。
閾値はS900/A750/B550/C350/Dそれ未満。ノード数自体には減点しないが、探索は時間と資源を通じて間接的に減点される。
バックエンドは別計算・S〜Cで、警戒度等による昇格条件もある。表示とログの評価は一般には一致しない。

- 残資源1＝15点、警戒度1ポイント＝8点、追加30秒＝15点。補給を多く残すことが強く評価される。
- 安全・資源ルートも評価要素には含まれるが、鍵付き安全例は最短例より37点低い。
- E03始動の安全経路が1005点なので、Sを取るために安全に遠回りする必要が薄い。
- 警戒度を一時的に上げ、後で消した攻略と終始低警戒だった攻略を最終値だけでは区別できない。
- 通常の回復で得点を稼ぐのは基本的に不利。時間減点発生後なら資源+5の75点に対し警戒度−84点・時間−15点で差し引き−24点。補給目的と回復目的は区別すべき。

### 評価変更の検討案（未実装・採用値ではない）

1. APIと画面で最終的に一つの評価仕様を共有する。D追加やレスポンス変更時は契約・型・Mockを同時更新する。
2. 時間・隠密・資源効率を内訳表示し、総合ランクとは別に長所が分かるようにする。
3. 時間猶予200秒→300〜330秒、残資源加点に上限10などを実験候補とする。一律のノード数加点は不要な寄り道を促すため避ける。
4. 鍵・防衛妨害は実際の有用性を先に整理する。単に追加点だけで必須化しない。

例として猶予300秒・残資源加点上限10、その他現行のままとすると、上記3例は最短942/S・安全943/S・資源788/A。
安全は救えるが資源例を下げるため、この案をそのまま採用しない。3軸の正規化や閾値も含め、代表手順を同時に比較する必要がある。
