# ステージ1：戦略性改善の実装報告

## 実装した仕様

- ターン制を維持。初期資源25、上限30、基本行動コストを変更していない。
- 初期入口は各ステージの`entry_node_ids`で指定。本編はE01のみ、訓練はexternal-1。
- 初期状態ではE02/E03へのscan・remoteScan・breachを`node_unreachable`で拒否。E01をスキャンするだけでは解放されず、侵入後に隣接先へ通常スキャン・侵入できる。
- remoteScanはE01侵入後に遠隔の未スキャンノードを調べられる。遠隔調査しても侵入の隣接・権限条件は迂回できない。
- データ回収を含む時間消費行動で警戒度100に到達すると敗北を優先。資源と時間は消費するが、検知した侵入・スキャンは完了せず、ノード効果や勝利ログも発生しない。
- 鍵2個の回収軽減は警戒度加算前に適用する。99%から鍵なしで回収すると100%で敗北、鍵2個ありなら98.25%で勝利。
- 入口をマップ・詳細パネル・開始ログ・ミッション説明で明示。訓練の画面遷移、リザルトのRETRY/TITLE、資源0からの回復を維持。

## 全経路と最短性の検証

- E01からC03までの全単純経路は3,394本。ノード数別では最短7ノードが2本、8ノードが13本。
- 7ノード以内の全連結攻略集合を列挙し、分岐・取得順を使っても7ノード未満で目標に届かず、7ノード攻略集合が2つだけであることをテスト。
- 最短2本は下記。どちらも数値的な補給・警戒度低減を含まず、通常操作で225秒・47.75%・資源1となる。2本目は鍵Aを1個取得するが、鍵Bがないため回収軽減は発動しない。
  - E01 → D01 → D04 → I02 → I10 → C02 → C03
  - E01 → D02 → D05 → I06 → I10 → C02 → C03
- 7/8ノードの全15経路を実際のAPIで再生。資源不足の場合のみ回復を挿入し、全経路で勝利、回復は最大1回。代表3方針では回復不要。
- リモートスキャンは通常スキャンより時間を使い、侵入の接続条件も省略できない。回復にも時間がかかるため、これらで225秒を短縮することはできない。

## 代表3方針の実行結果

条件：初期状態から各ノードを通常スキャン→侵入、最後にC03回収。時間は操作で進むゲーム内時間。

| 方針 | 取得順序 |
|---|---|
| 最短 | E01 → D01 → D04 → I02 → I10 → C02 → C03 |
| 安全・鍵回収 | E01 → D02 → D05 → I06 → I07 → I09 → C04 → C03 |
| 資源回収 | E01 → E03 → D06 → I05 → I06 → I10 → C02 → C03 |

| 指標 | 最短 | 安全・鍵回収 | 資源回収 |
|---|---:|---:|---:|
| 侵入ノード数 | 7 | 8 | 8 |
| 操作数 | 15 | 17 | 17 |
| 時間 | 225秒（3:45） | 255秒（4:15） | 255秒（4:15） |
| 資源総消費 | 24 | 27 | 27 |
| 資源報酬合計 | 0 | +3 | +15 |
| 残資源 | 1 | 1 | 13 |
| 最終警戒度 | 47.75% | 18.25% | 45.25% |
| アクション確定後の警戒度ピーク | 47.75% | 29% | 45.25% |
| 鍵 | なし | 2個 | Aのみ |
| 回復回数 | 0 | 0 | 0 |
| 最終権限 | ROOT | ROOT | ROOT |
| 得点・ランク | 771 / A | 911 / S | 866 / A |

- 最短は30秒速い反面、残資源1で追加探索の余裕がなく、警戒度も高め。回復や探索を挟むと最短時間ではなくなる。
- 安全は30秒追加で警戒度を抑え、鍵で高警戒時の回収も安全にできる。ただし資源の余裕は少ない。
- 資源回収は30秒追加で資源13を残せるが、安全側より警戒度が高い。以降の探索や回復回数の削減に向く。

別の低警戒例 `E01 → E03 → D06 → I03 → I04 → I09 → C04 → C03` は255秒・14.75%・資源6・979点S。
初期警戒度0のこの手順では鍵ルートより良い最終値になるが、鍵を持たないので高警戒からの回収軽減はない。
どの手順も全ての指標で最善ではなく、最短225秒に安全・大きな補給が集中する状態は解消した。
これらは無駄な探索のない決定的な手順の比較であり、初見プレイヤーの難易度を保証するものではない。

## 評価の統一

係数の元データは`backend/balance_config.py`の`EVALUATION_CONFIG`のみ。
生成スクリプトでフロントへ同期し、バックエンドAPI・ログ・Mock・画面で同じ式とS/A/B/C/Dを使用する。
HTTP接続時はAPIのevaluationを表示。未対応の保存状態等でevaluationがない場合だけ、同じ共有式で算出する。

得点 = max(0, floor(1000 − max(0, 経過秒−240)×0.5 − 警戒度×5 ＋ min(10, 残資源)×10 ＋ 0.5))

警戒度はAPIと同じ小数2桁。900以上S、750以上A、550以上B、350以上C、それ未満D。
従来のバックエンド側の警戒度だけによる別昇格を廃止した。

- 時間猶予は200→240秒、警戒度減点は8→5、資源加点は15→10、資源加点対象は10まで。
- ノード数の直接加点なし。無報酬の余分な攻略は時間・警戒度・資源の負担となる。
- 回復の資源加点は最大50点に対し、警戒度コストが52.5点、猶予時間超過後はさらに15点減。回復連打で得点を増やせない。
- 資源0〜29、経過0/240/600秒の90条件で回復によって得点が増えないことをテスト。実APIでも無用な回復・無報酬ノードの寄り道で得点が下がることを確認。
- 補給・痕跡削減等の有用な寄り道は評価される。純粋な攻略数稼ぎの加点はない。

## 残る確認

- 実ブラウザでの目視プレイ、初見のプレイテストは未実施。画面の自動検証は描画結果・操作条件・状態遷移のテストでありブラウザE2Eではない。
- 初見での迷いや追加探索に対する難易度は、プレイテストで調整する。最短が資源1を残す設計なので、寄り道時に回復が必要になる場合がある。
- 既存セーブの攻略済み状態は消さない。新しい入口・経路バランスを試すときはRETRY/リセットで新規状態から開始する。
- 新しい5段階評価は今後の勝利時に適用される。既存セーブの古いログは履歴として保持するため、過去の評価ログを遡って書き換えない。
- コミット・プッシュは実行していない。
